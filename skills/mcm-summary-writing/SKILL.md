# 美赛摘要写作

这是一套用户个人写作规范。MCM/ICM 与 HiMCM/MidMCM 共用内容组织方法，实际提交格式分别服从指定赛事、年份和模板。下面的逐题句式与加粗要求是个人偏好，不应称为赛事官方规定。用户当前明确要求优先。

## 先确定任务范围

- 用户只讨论规范时，先讨论；要求撰写、修改或排版时，完成对应工作。
- 优先读取用户指定的完整论文、题目和已有摘要。工作目录已有材料时先定位本地材料，不为同一资料重复联网搜索。只有要求寻找优秀论文时才选取论文，并核实获奖来源。
- 数学表达优先读 LaTeX；只有 PDF 或 Word 时正常处理，核对公式、表格和符号，不要求用户为了格式重新提交材料。
- 沿用明确指定的输出语言、交付方式和编辑对象。中文讨论不自动改变英文文档的语言；只要中文摘要时直接在聊天中输出，不额外制作文档。
- 资料足够就继续。缺少完整论文时，不把已有摘要当成读过全文；先利用现有材料处理可确定部分，仅询问影响内容真实性的缺失信息。

## 写作前的内容依据

按实际问题梳理目的、数据及预处理、模型和关键方法、结果及单位、情景条件、验证和局限。工作笔记中保留数值与原文位置的对应，默认不把笔记附在最终摘要后。

保留真实的模型联系；只有前一模型的结果确实参与后一模型时才描述输入输出关系。不得为满足段落模板编造创新、置信区间、敏感性结论、最优性或验证结果。区分预测、模拟、方案估计和实际观测；不能把候选站点说成已实施布局。遇到原文数字冲突，核对上下文和计算依据，未解决前不用争议数字支撑强结论。

## 段落与句式

三个实质问题通常采用五段：开篇、三个问题段、验证与结论。问题数量改变时按实际结构调整，不强凑三个模型。开篇和收尾各以 2–3 句为起点，核心段各以 4–6 句为起点，最后按信息完整性和页面容量调整。

每个核心段遵循以下硬要求，压缩和翻译后也要保留：

1. **第一句以“针对问题一，”“针对问题二，”等开头；英文以“For Problem 1,”、“For Problem 2,”等开头。** 第一整句说明该问题要解决什么。
2. **第二句明确说明建立了什么模型。** 例如“我们建立了基于回归分析的环境影响评估模型。”或“We develop an environmental impact assessment model using regression analysis.” 不把建模句提前并入第一句。
3. 后续说明必要的数据处理、核心方法和真实模型联系，以关键定量结果、单位、条件或有依据的建议完成该段。

开篇交代背景、目标和主要模型数量及名称或功能；避免宏大背景铺垫。收尾优先呈现已做的验证、敏感性分析和适用边界，不重复三个问题段的结论。具体句子角色与原始提示词的调整见 [写作要求与沿革](references/requirements-and-examples.md)。

## 语言与模型命名

- 行文平实、专业、严谨、学术化，用词冷静克制。删除宣传性评价、夸张比喻和无证据的可靠性断言。
- “高级”的模型名称应体现准确的研究对象和方法。使用领域认可的术语或透明、准确的描述性名称，不堆叠修饰语，不把描述性名称包装成公认的新算法。
- 对不熟悉的术语，核对论文及必要的权威来源；无法确认时采用清楚的普通学术表述。不得为追求名称气势造词再增补解释。
- `not ... but ...`、`rather than` 及中文同类结构仅用于真实且必要的对比。避免滥用引号、冒号、破折号，以及依赖括注、插入语补救含混表述的写法。正常单位、公式和必要的技术说明不应机械删除。
- 英文润色保持原有技术含义、数值精度和限定条件，处理术语、时态、语法与自然衔接。无需套用 IEEE 版式，也无需用复杂句证明“学术性”。

## 加粗与一页容量

- 整体加粗每个核心段的 **“针对问题几，”或“For Problem N,”**，包括该引导语中的逗号。
- 模型名称、少量核心方法、关键数字与相应结果含义、主要验证指标也应有选择地加粗，使重点分布于各核心段；不整段加粗，不只加粗模型名。
- 摘要必须完整留在第一页，并尽量合理利用可用空间。依据实际目标模板的编译与预览判断，不能把固定英文词数当成一页保证。
- 过长时先删重复解释、次要过程、空泛修饰和非核心算法细节，保留问题、模型、关键结果、单位及条件。过短时补充原文支持且尚未交代的数据、方法依据、模型联系、结果、验证或边界，按段落需要分配，不能单段堆砌或添加套话。
- 保持既定字体、字号、行距和页边距；没有相应要求时，不通过缩小版式参数满足一页。

## LaTeX 编辑与检查

仅在用户要求模板试排或编辑 LaTeX 时读取 [模板与版面检查](references/latex-layout.md)。已有编辑器文档时在原文件中修改，保持原编辑器；用内置编译器检查。未经请求不替换文档、不另行编译独立 PDF、不打开另一标签页。

第一段与后续正文使用一致首行缩进；保留标题、必要页眉和关键词。清理模板中的填写说明文字，但继续遵守其中适用的匿名和提交要求。

## 交付前检查

- 核心段引导语、第二句建模、专业命名、真实数字及条件是否完整？
- 有无夸大、臆造联系、无依据的“稳定”“显著”“最优”，或为补版面重复说明？
- 加粗能否突出问题、方法和结果；首段是否缩进；关键词是否完整？
- 涉及排版时，最后修改后的文件是否编译，摘要是否确实在第一页内？分别说明编译状态与实际版面核查状态，不能用编译成功代替视觉核查。
- 最终输出按用户要求给摘要或文件；没有要求时不附逐句修改表、过程笔记或长篇说明。
