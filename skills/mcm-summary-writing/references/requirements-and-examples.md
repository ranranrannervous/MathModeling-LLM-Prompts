# 写作要求与沿革

在首次形成摘要结构、处理偏好冲突或复核要求覆盖时阅读。这里区分原始提示词、后续明确要求和具体试排案例，避免把一次案例的参数推广为所有论文的规定。

## 来源与优先级

原始依据为用户的 [MathModeling-LLM-Prompts 摘要提示词](https://github.com/ranranrannervous/MathModeling-LLM-Prompts/blob/4abb6708e399234745b8642786e581dee6dee194/README.md)，已在创建本技能时读取。该提示词要求先读完整论文，再逐段生成、压缩和英文润色。它原为 Claude Pro 编写；本技能保留写作方法，不依赖该平台，也不把原作者对效果的评价当作独立验证。

优先顺序：当前明确要求、此前已确认且仍适用的要求、原始提示词的一般建议。后续“专业克制、使用通行术语”的要求约束早期“模型名字要高级”；后续第二句建模覆盖原始第二句用于数据来源或创新介绍的安排。

## 完整要求对照

| 来源或阶段 | 最终采用的规范 |
| --- | --- |
| 最初研究 MCM/ICM 与 HiMCM | 提炼共用写作结构，分别核对目标比赛的模板和提交要求。 |
| GitHub 原始提示词 | 以完整论文为依据，按段落建立内容，再压缩和润色；数学符号优先读取 LaTeX。 |
| 原始开篇段 | 用 2–3 句说明背景与意义、研究目标、主要模型数量及名称或功能；仅表达真实的递进关系。 |
| 原始三个模型段 | 目的、数据与处理、方法、定量结果、实际意义构成主体；必要时说明模型间联系，段落以 4–6 句为起点。 |
| 原始验证段 | 用 2–3 句提供已完成的验证、参数变化范围、误差或适用价值；缺少依据的指标不补造。 |
| 原始创新与可靠性要求 | 只写论文支持的具体方法特征、验证和比较；采用成熟方法不自动构成创新。 |
| 原始图表引用要求 | 图表编号必须准确，引用服务于具体结论；不依赖“见表”替代结果，独立摘要避免悬空引用。 |
| 原始压缩要求 | 保持逻辑与关键内容，删重复术语解释、次要过程、冗余形容词和非核心细节，简化长句。 |
| 原始英文润色要求 | 技术内容不变，改善学术用词、语法、时态和衔接；不机械照搬 IEEE 版式或强制交付修改对照表。 |
| 测试材料要求 | 使用指定文件夹已有优秀论文及模板；先读正文，再重新组织摘要。案例改写不能声称是获奖论文原始摘要。 |
| 输出中文 | 要求中文直接输出时，在聊天中给中文摘要；英文版本及模板试排仅按实际任务提供。 |
| 逐问题开头 | 每个核心段第一句以“针对问题几，”或“For Problem N,”开头。 |
| 第二句建模 | 每个核心段的第二个完整句子明确“我们建立了……模型”；不得在压缩中合并掉这一位置要求。 |
| 模型名称要高级 | 使用专业、通行、能反映研究对象和方法的名称；不堆叠抽象修饰语或编造术语。 |
| 篇幅不能超出一页 | 在实际目标模板中检查，包括标题、页眉、段距和关键词的占用；中文长度不能保证英文版也能容纳。 |
| 尽量填满一页 | 补足各段缺失且有依据的信息，保留合理底部余量；不能为填满虚构内容、堆砌措辞或放宽证据标准。 |
| 删除模板提示语 | 定稿移除填写提示，不删除必要赛事字段，也不废除提示语中适用的匿名要求。 |
| 第一段首行缩进 | 标题后的第一段也按正文缩进，不能只让后续段落缩进。 |
| 增加加粗 | 完整加粗逐题引导语，并分散突出模型名、关键方法、主要结果及验证指标；避免整段加粗。 |
| 最终语言风格 | 平实、专业、严谨、学术化，冷静克制；不用夸张奇怪的比喻和修辞。 |
| 对比结构 | `not ... but ...`、`rather than` 及同类表达仅服务于必要的真实对比。 |
| 标点与解释 | 不滥用引号、冒号、破折号及增补式解释；优先让主句清楚完整，避免必须补解释的生造词。 |
| 专业术语 | 使用前确认其含义和领域用法；普通准确表述优于含义含混的包装。 |
| 现有 LaTeX 文档 | 读取并原位编辑，使用内置编译检查，保持当前编辑器；不擅自创建替代文档或单独 PDF。 |

## 段落组织示例

以下是句子角色，不能当作填空后就自动成立的事实。

### 开篇

1. 指出研究对象和需要处理的实际问题。
2. 给出论文具体目标及必要的时间或情景范围。
3. 简述实际使用的主要模型数量与功能；名称过长时使用准确简称或功能描述。

### 每个核心段

1. **针对问题几，**概括研究目标。
2. 我们建立了**某模型**，必要时在同句写明其主要方法。
3. 说明理解结果所必需的数据、预处理、方法或假设。
4. 说明关键计算方法，或与其他模型的真实联系。
5. 给出关键结果及单位、基准或情景条件。
6. 有必要时给出另一主要结果、验证或有依据的决策含义。

第 3–6 句可随证据和篇幅合并、删减或调整顺序。不能为了凑句数逐项罗列算法步骤。某题包含多个子模型时，准确概括整体方法，并在后续说明子模型分工，不强行把每个问题变成一个全新算法。

中英文开头示例：

> **针对问题一，**我们估计公交车队电动化对温室气体排放和噪声的影响。我们建立了基于回归分析的**环境影响评估模型**。

> **For Problem 1,** we estimate changes in greenhouse gas emissions and noise associated with fleet electrification. We develop an **environmental impact assessment model** using regression analysis.

这些示例仅说明句式，不应把公交车队模型迁移到其他题目。模型名应区分描述性任务名称与已有算法名称，如环境影响评估模型、财务预测模型属于描述性名称，TOPSIS、K-means 属于实际方法。不要把“财务预测模型”修饰成含义不清的“多源资金驱动动态财务递推协同框架”。

### 验证与结论

优先给出验证方式、样本划分、误差指标或有意义的基准比较；再写已有敏感性分析的扰动范围及实际观察到的影响；必要时说明最影响解释的假设、适用范围或局限。

只知道“参数扰动 ±10%”不能推出“结果稳定”或填写误差界限。没有独立验证时不能把拟合优度写成预测准确率。没有置信区间时不补写置信度。

## 篇幅调整顺序

超页时，优先保留逐题句式、模型、主要发现、数值和条件。先删除宣传性或重复内容，再压缩次要过程和算法细节，最后比较各段信息价值做取舍。只提到数值而不保留其单位、基准或条件，会改变结论，不能视为有效压缩。

明显留白时，先判断哪一段缺少解释结果所必需的信息。可补数据来源与处理、模型选择依据、真实联系、主要结果、验证对照或适用边界。不能把所有补充都集中到已经完整的一段，也不能仅增加连接词和形容词。

没有更多有价值的信息时保留空白。一次试排得到的词数只描述该次文档，不能成为每次写作的最低词数或一页保证。
